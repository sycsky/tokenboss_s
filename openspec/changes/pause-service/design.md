# 服务暂停设计

状态：用户已确认第二版原型并授权继续；随后明确仅修改前端。本地实施与验证完成，尚未部署或迁移。

## 已选方向与取舍

- 保留现有网站，在顶部加入浅黄色公告条；与把网站直接替换成停服页相比，保留已有品牌及公开资料。
- 登录、注册、充值入口统一落到说明页；与弹窗相比，完整页面可独立访问、分享、刷新，并可在后端关闭后静态托管。
- 页脚持续保留退款邮箱，退款政策顶部增加专项说明。
- 当前前端视觉沿用米白底、橙色品牌、深色描边与硬阴影。

这些位置和样式方向已由用户确认。原型将其具象化，供最终视觉验收。

## 原型范围

`mock/index.html` 包含首页、说明页、套餐入口、退款政策四种视图；支持桌面/手机及停服前/后切换。

- 首页顶部直接显示完整日期、退款邮箱与详情入口；其他页面使用紧凑公告。
- 点击登录可进入说明页，并显示“登录功能已关闭”的上下文提示。
- 邮件按钮仅生成预填主题与两项信息标签的 `mailto:`，不自动发送邮件。
- 复制邮箱提供成功反馈；剪贴板不可用时提示手动复制。
- 停服前后通过原型工具栏模拟，原型不执行真实业务截止任务。
- 原型只覆盖变动涉及的区域，未完整复制原官网。原首页保留的其他资料在正式开发时沿用现有组件。
- **用户最新修正**：首页只通过顶部公告集中提示停服，撤掉原型新增的“服务状态”卡片及 slogan 下方重复的停服段落。保留原品牌 slogan 与一般产品介绍；原型不再增加右侧提示模块。其他原注册、登录、充值入口统一标为“停服说明”，完整安排集中在说明页。
- 套餐卡片在原型中仅展示名称和停售信息；正式页面保留多少价格/配额资料随视觉验收确定，不将原型简化擅自解释为删减业务资料的授权。

## 当前实现边界（用户最新修正）

- 仅修改 `frontend/` 与本次需求文档。后端 handler、模型截止、支付、数据库及 Agent skill 保持原样。
- 公告与退款信息独立于认证加载；旧业务页面在前端改为公开说明页，隐藏充值等入口。
- 旧会话不主动注销，账户/用量/订单查看保留；充值/兑换/购买入口替换为停服说明。
- 日期只控制页面时态，不能将前端公告解释为服务端已拒绝请求。
- 原型中“关闭功能”的表述在正式页面收敛为“网站已关闭入口”，不宣传后端封禁。

## 验收安排

前端单元测试覆盖公告、旧页面直接访问、日期切换、邮箱与复制兜底、已登录用户入口。类型检查与构建、浏览器宽度与旧后端不可访问检查通过后交接。后端 diff 必须为空。

## 迁移阶段

新托管平台、域名切换、TokenBoss 与 newapi 数据备份/恢复读取验证、邮箱持续收信需要另行核查。静态网页可以迁移，不等于用户资产与退款依据已经保全。当前文件不作为已完成迁移的证明。
