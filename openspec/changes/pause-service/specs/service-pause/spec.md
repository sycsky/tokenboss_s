# Service Pause — Frontend Only

状态：已按用户最新范围修正，仅前端实施；后端规则不在本次范围。

## Requirement: 顶部公告

网站 MUST 在导航栏上方展示浅黄色公告条，包含“2026 年 12 月 16 日 00:00（北京时间）暂停服务”；首页直接展示退款邮箱与说明入口。公告不依赖登录或后端请求成功。

### Scenario: 查看首页

- **GIVEN** 本次前端更新上线
- **WHEN** 访客或已有会话用户访问首页
- **THEN** 顶部显示日期、网站已关闭相关入口及 `shawn@tokenboss.co`
- **AND** 页面保留原 slogan，不新增旁侧状态卡片或下方重复停服段落
- **AND** 公告不可关闭，手机完整换行且无横向溢出

### Scenario: 跨过公告时间

- **WHEN** 浏览器打开页面或持续停留跨过公告时间
- **THEN** 前端改为“已于”暂停服务的表述，不继续提示已有 Key 可在停服前使用
- **AND** 不因此执行后端 API、密钥或支付变更

## Requirement: 收敛前端入口

网站 MUST 隐藏或替换注册、登录、购买、充值、续费和兑换入口；说明入口统一使用“停服说明”，不再打开业务表单或支付弹窗。

### Scenario: 从原按钮进入

- **WHEN** 用户查看导航、首页、套餐、控制台、账户设置或接入页
- **THEN** 不再出现可进行新注册、登录、付款、续费或兑换的入口
- **AND** 原位置可显示“停服说明”并进入统一说明页
- **AND** 试用赠额标签和鼓励新增付费的操作引导撤下

### Scenario: 直接访问旧页面

- **WHEN** 用户直接访问 `/login`、`/register`、`/login/magic`、`/verify-email`、`/oauth/callback`、`/billing/topup` 或 `/billing/pay`
- **THEN** 显示公开停服说明，而非认证或付款表单
- **AND** OAuth 回调中的 token 不被页面接纳为新会话
- **AND** 说明页不以登录为前提

### Scenario: 已有有效会话

- **WHEN** 已登录用户访问账户、余额、用量及订单
- **THEN** 保留原有查看能力，不主动注销、删除 Key 或改变后端数据
- **AND** 充值、续费、兑换入口同样不可操作

## Requirement: 退款联系

说明页 MUST 展示 `shawn@tokenboss.co`，要求提供登录邮箱与联系微信，并说明后续联系核实处理。

### Scenario: 申请退款

- **WHEN** 用户访问说明页
- **THEN** 可点击预填主题和两项信息标签的邮件链接，或复制邮箱
- **AND** 剪贴板不可用时可手动复制，且按钮给出相应反馈
- **AND** 不自动发送邮件、不要求登录、不承诺退款金额或时限

### Scenario: 退款政策及页脚

- **WHEN** 用户查看 `/refund` 或页脚
- **THEN** 能找到同一邮箱与停服说明
- **AND** 常规“不支持退款”条款不否定本次申请的提交与核实

## Requirement: 严格前端边界

本次 MUST NOT 修改后端 handler、支付确认、数据库、模型请求逻辑或 API Key；不增加服务端截止任务。旧后端不可访问时，首页与说明信息仍应可阅读。

网站迁移、实际停服、DNS、退款数据备份与邮箱收信验收另行落实，不视为本次已经完成。
